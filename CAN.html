Arbitration — The Hero Feature

non-destructive, bit-by-bit

Two nodes start transmitting at the same instant. Every identifier bit is compared against the resulting bus value. The moment a node sends recessive (1) but observes dominant (0), it has lost — and stops, without corrupting the winner's frame.

CAN FD — Bit-Rate Switching

flexible data-rate

CAN FD keeps the arbitration phase at the nominal bit rate (for compatibility and priority resolution), then switches to a faster data bit rate for the payload and CRC, before dropping back to nominal for the rest of the frame.

DLC-to-length is not linear above 8 bytes in CAN FD: DLC 9→12B, 10→16B, 11→20B, 12→24B, 13→32B, 14→48B, 15→64B.

Signal Decoder

application layer, not CAN itself

A CAN frame just carries raw bytes. A signal database defines how to slice bits out of the payload and turn them into an engineering value — this is layered on top of CAN, not part of the protocol.

Protocol Layering

A raw CAN frame is not UDS, CANopen, or J1939. Those are higher-level protocols that define how to interpret identifiers and payload bytes; CAN only guarantees delivery, priority, and error handling of the frame itself.

ECU Internal Path

APP LOGIC → TX MAILBOX → CAN CONTROLLER (arbitration, stuffing, CRC) → CAN TRANSCEIVER → CAN-H / CAN-L

CAN-H / CAN-L → TRANSCEIVER → CONTROLLER → ACCEPTANCE FILTER → RX FIFO → INTERRUPT → CPU

Not every received frame reaches the application — the acceptance filter can silently drop frames outside its configured ID range/mask before they ever reach the RX FIFO.
